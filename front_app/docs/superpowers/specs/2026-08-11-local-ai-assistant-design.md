# 本地 AI 科研助手设计

**日期：** 2026-08-11
**状态：** 已确认
**范围：** Flutter Windows 单机版个人工作台的“科研 → AI 助手”

## 1. 目标

把当前依赖不存在的 `/api/v1/agent/*` 后端的 Agent，替换为可在单机版直接使用的科研对话助手：

- 只从“科研”工作区进入，不增加全局 AI 导航。
- 支持 DeepSeek、OpenAI、Moonshot、智谱、Ollama 和自定义 OpenAI-compatible 服务。
- 对话与会话历史只保存在本地 SQLite，并随普通本地备份恢复。
- API Key 只保存在 Windows Credential Manager，不进入 SQLite、偏好、日志或备份。
- 软件启动、打开科研页和打开 AI 面板时都不联网；只有用户主动发送消息时才请求所选服务。
- 保持说明文字克制，优先把“能配置、能发送、能恢复历史、错误说清楚”做好。

第一版不包含联网搜索、函数工具调用、文件全文自动上传、RAG、语音、多设备同步或账号体系。

## 2. 已确认方案与取舍

采用“多供应商 OpenAI-compatible 直连”方案。应用直接调用供应商的 `/chat/completions` 接口，不再要求部署旧后端。OpenAI-compatible 形状也可覆盖本地 Ollama；各供应商的 Base URL 和模型名允许用户修改，避免硬编码模型下线后必须升级应用。

不采用 Ollama-only，因为它会把可用性限制在本机已部署模型的用户；不保留旧后端方案，因为当前项目没有该后端，且它与单机本地版方向冲突。

协议依据：DeepSeek 官方接口为 `/chat/completions` 且多轮上下文由客户端重传；Ollama 官方提供部分 OpenAI API 兼容；OpenAI、Moonshot、智谱均由同一客户端适配层处理，供应商差异限定在预设、认证和可选请求字段内。

供应商预设在实现时按各自官方文档的当前 Base URL 和模型标识写入；模型名与地址始终可编辑，自定义供应商不附带默认值。

## 3. 架构边界

### 3.1 `AiCredentialStore`

职责只有保存、读取和删除密钥。生产实现调用 Windows Credential Manager，目标名使用稳定前缀 `research-life-app/ai/<profile-id>`；测试使用内存实现。

接口不暴露枚举全部系统凭据的能力，也不把密钥包装进可序列化模型。错误文本只能说明“凭据读取失败”，不得包含 Key、Authorization header 或完整请求。

### 3.2 `AiProfileRepository`

保存非敏感配置：profile id、供应商、显示名、Base URL、模型名、是否需要 Key、创建/更新时间。第一版只维护一个当前配置，但数据结构保留稳定 id，便于以后增加多个 profile，而不在本次实现 profile 管理 UI。

配置以一条非敏感 JSON 记录放在 Drift 的 `Preferences` 表中，并参与全局 `LocalDataOperationCoordinator` 写屏障。`hasCredential` 每次由 credential store 查询得到，不持久化，避免凭据被外部删除后仍显示为可用。

### 3.3 `AgentChatRepository`

新增本地会话表和消息表。会话记录标题、所用 profile/model、创建与更新时间；消息记录 session id、role、content、model、创建时间。删除会话在一个数据库事务中删除其消息。

所有写入进入应用级写协调器，因此手动备份不会与新消息提交交错。数据库备份自然包含历史记录；恢复到另一台或清除 Windows 凭据后，历史仍可读，但再次发送前必须重新输入 Key。

### 3.4 `OpenAiCompatibleChatClient`

使用现有 Dio 发起 JSON 请求。客户端接收已经解析好的非敏感 profile、调用时临时读取到的 Key，以及当前会话消息；统一构造 Bearer 认证与 `/chat/completions` 请求。Ollama 允许无 Key。

第一版采用非流式响应，界面显示明确的发送状态，降低不同供应商 SSE 差异带来的失败面。后续可在不改仓储和控制器接口的情况下增加流式实现。

客户端只返回规范化结果：回答正文、可选 reasoning、实际模型名和 finish reason。供应商响应解析失败、空回答、超时、401/403、429、5xx 分别转换成短而可操作的中文错误。

### 3.5 `AgentController`

控制器不再依赖 `AgentApi`。它协调本地仓储、凭据存储和直连客户端：加载会话、打开历史、新建/删除会话、发送消息、失败重试。

发送顺序固定为：

1. 校验配置，并只在这时读取凭据。
2. 在本地创建会话（若需要）并保存用户消息。
3. 从本地读取该会话上下文，调用供应商。
4. 成功后保存助手消息并更新会话标题/时间。
5. 失败时保留用户消息，显示错误和“重试”，不伪造助手消息。

同一控制器只允许一个发送操作。关闭 AI 面板不取消已进入本地提交阶段的数据；网络请求可取消，取消不显示为系统错误。

## 4. 界面设计

AI 仍以“科研”页右上角主操作打开全屏工作区，不在 Today、Life、Settings 或全局侧栏重复入口。

工作区结构：

- 左侧窄历史栏：新对话、会话标题、删除；支持收起。
- 中部对话区：空状态只显示一句引导；消息气泡、Markdown 回答、发送状态与错误重试。
- 底部输入区：多行输入、发送按钮、当前供应商/模型短标签。
- 右上角齿轮：打开 AI 配置对话框。

配置对话框包含供应商、Base URL、模型名、API Key 和“保存”。API Key 输入默认为空且不可回显；为空表示保留已有凭据，另提供明确的“删除凭据”。Ollama 选择后将 Key 标记为非必需。

删除旧的“快速/专家/深度思考”伪模式控件。第一版只呈现真实可验证的能力，避免用户误以为所有供应商都支持相同推理参数。

配置区显示一句隐私提示：发送消息时，对话上下文会传给当前所选服务；本地历史和凭据的保存位置分开。

## 5. 数据与迁移

Drift schema 从 8 升级到 9，新增：

- `agent_chat_sessions`
- `agent_chat_messages`

现有 `AgentChatSession` / `AgentChatMessage` 领域模型改为本地 id 语义，避免复用旧服务端 id 假设。旧 `/api/v1/agent/*` 客户端和对应 JSON 解析路径在迁移完成后删除。

旧数据库中可能存在的 `agentLlmSettings`、`remoteLlmAnalysisSettings` 明文配置继续保持 dormant，不在安全备份完成前主动删除；运行时永不读取这些值来启用 AI，备份副本继续物理脱敏。新 Key 只写 Credential Manager。

## 6. 错误与恢复

- 未配置：在 AI 工作区直接显示“配置 AI”，不把用户送到全局 Settings。
- 凭据缺失：保留 profile 元数据，提示重新输入 Key。
- 网络不可达/超时：保留用户消息，可原地重试。
- 认证失败：提示检查 Key，不清除凭据，避免瞬时服务错误导致数据丢失。
- 限流：提示稍后重试。
- 模型或 Base URL 无效：提示打开配置并保留输入。
- 本地保存失败：不发起网络请求；先保证本地记录可恢复。
- 回答成功但本地保存失败：保留屏幕中的回答并提示未写入历史，不把失败伪装成发送失败。

任何错误不得记录请求 Authorization、Key、完整数据库行或用户对话正文到默认日志。

## 7. 测试与验收

实现必须按 RED → GREEN 推进，至少覆盖：

1. Credential store：写入、读取、删除、缺失；生产边界不把 Key 写入普通文件。
2. 数据库迁移：schema 8 → 9；会话/消息增删和级联删除。
3. 备份安全：seed 新旧密钥后，备份数据库和 manifest 的原始字节都不含密钥；本地聊天历史可恢复。
4. HTTP 合约：URL 规范化、Bearer header、Ollama 无 Key、消息顺序、成功响应、空响应、401、429、超时与取消。
5. 控制器：无配置不发送；失败保留用户消息；重试不重复用户消息；同一时刻只发送一次。
6. UI：科研唯一入口、配置弹窗、Key 不回显、模型标签、历史打开/删除、错误重试。
7. 启动边界：配置了远程供应商也不在 runtime open、科研页打开或 Agent bootstrap 时联网。

最终验收需要：相关 Flutter tests 全绿、完整测试套件全绿、`dart analyze` 无新增 warning/error，并在 Windows 原生窗口中手动验证一次配置、发送、重启后历史保留和删除凭据后的提示。

## 8. 明确不做

- 不复用 Codex 自身 OAuth 或 Codex provider 配置。
- 不把 API Key 放入环境变量作为主要用户流程。
- 不把对话自动同步到任何云端。
- 不在后台预热模型或测试连接。
- 不自动把 PDF、笔记或选中文本发送给供应商。
- 不在本轮接入分析页的周复盘 AI；该功能后续可复用同一安全 profile，但需要单独设计与授权。
