# 研LIFE 个人工作台精修与 Web 预览设计

日期：2026-08-09  
状态：已完成方案讨论，待用户审核书面规格

## 1. 目标与边界

研LIFE 是 Flutter Windows 个人工作台，科研与生活的产品权重各占一半。HTML/Web 只承担设计预览，不替代 Flutter 应用，也不连接真实后端或读取个人数据。

本阶段先交付可交互的 Web 预览，确认导航、布局、毛玻璃、色彩、密度和动效；用户确认后，才制定并执行 Flutter 改造计划。

本轮不重写业务功能，不更换 Flutter 技术栈，不把 Web 原型演变成正式产品。

## 2. 已确认的设计原则

1. 科研与生活并重，不把生活功能处理成科研模块的附属入口。
2. 页面说明文字克制：标题下最多一行短说明；卡片不重复解释标题；空状态只保留一句引导和一个主要操作。
3. 采用“分层式精修”，保留学术绿品牌基础，重做信息层级与组件一致性。
4. 适量使用 iOS 风格毛玻璃，但不铺满列表、文件区、阅读正文或滚动卡片。
5. 天气页是全局固定入口和手动待机展示页；不使用闲置计时或自动跳转。
6. Web 预览必须包含可操作导航，确认后再修改 Flutter。

## 3. 信息架构

### 3.1 一级导航

侧栏按以下顺序组织：

- 品牌区与全局搜索
- 天气待机页（全局固定入口）
- 今日
- 科研
- 资料
- 生活
- 设置（固定在底部）

AI 助手归入科研工作区，不与一级工作区并列。历史记录改成相关页面的回溯入口，不长期占用主导航。文档查阅由资料或文献上下文打开，不作为一级导航项。

### 3.2 二级导航

二级导航使用页面标题下方的短横向标签，不增加第二条侧边栏。

| 工作区 | 二级入口 |
| --- | --- |
| 今日 | 今天、日历、待办 |
| 科研 | 概览、文献、笔记、周分析、人物、统计 |
| 资料 | 文件、文档查看、PDF 工具 |
| 生活 | 校园、桌宠、个性化 |

切换二级入口时保留筛选条件、选中项目和滚动位置。

## 4. 应用壳层

- 侧栏展开宽度约 216px，收起宽度约 68px。
- 选中项使用浅色背景、左侧强调线和图标变色，不使用面积过大的白色胶囊。
- 普通页面具有统一的页面标题、可选短说明、二级导航和不超过三个主操作。
- 全局搜索、同步状态等壳层信息不在各页面重复实现。
- 收起侧栏后保留图标、选中状态和 Tooltip。

### 4.1 天气待机页

- 只能由用户手动打开。
- 全幅展示时间、日期、天气状态、天气动画和少量今日信息。
- 进入后侧栏淡出；鼠标靠近左侧时恢复，按 `Esc` 或返回操作回到进入前的页面、选中项和滚动位置。
- 提供关闭天气动画、减少动态效果和减少透明效果的设置能力。

## 5. 代表性页面

### 5.1 今日

“今天”默认采用左侧时间线、右侧待办的双栏结构。快速记录是页面右上角的主要操作。日历与待办仍有独立二级页面，但不再作为一级导航散落在侧栏。

### 5.2 科研概览

只呈现最近阅读、待整理笔记、本周计划和周分析入口。避免密集数据大屏和无行动意义的统计卡。AI 助手作为科研页右上角的辅助操作，可进入完整会话页面。

### 5.3 资料文件工作台

采用左侧目录、中央文件列表、右侧详情的桌面工具布局。文档查看和 PDF 工具通过二级导航或选中文件的上下文操作进入。

### 5.4 生活

首版 Web 预览只保留可识别的导航与简洁占位状态。Flutter 实施阶段再分别承接校园地图、桌宠和个性化能力。

## 6. 视觉系统

- 保留学术绿与浅色内容区。
- 应用外壳圆角约 18–20px；普通面板 12–14px；按钮和输入框约 10px。
- 同一页面最多使用一级轻阴影，其余层级使用背景明度和细边框表达。
- 页面标题约 24px，区块标题约 16px，正文 14px；12px 只用于必要的辅助信息。
- 外层间距统一为 24–32px，内部使用 8px 网格。
- 图标使用同一套圆角风格，保持一致的线宽、尺寸与选中反馈。
- 每页原则上只有一个主要按钮；次要操作进入工具栏或更多菜单。
- 功能动效约 140–220ms，并尊重系统“减少动态效果”。
- 现有主题可以保留，但只改变颜色，不改变组件结构、排版、间距与信息层级。

### 6.1 毛玻璃规则

允许使用毛玻璃的区域：天气页信息浮层、侧栏品牌/搜索区、浮动工具栏、对话框、快捷操作面板和状态提示。

禁止把毛玻璃用作普通滚动列表、文件表格、阅读正文、PDF 内容底板或每张统计卡的通用样式。Flutter 实现需限制同时存在的 `BackdropFilter` 数量，并为低性能与减少透明模式提供不透明降级表面。

## 7. Web 预览交付

Web 预览是纯演示数据驱动的交互原型，覆盖：

1. 天气待机页。
2. 今日工作区。
3. 科研概览。
4. 资料文件工作台。
5. 完整展开/收起侧栏与二级导航。
6. 生活与设置的可识别占位入口。

必须支持：页面切换、侧栏展开/收起、二级标签切换、项目选中、局部内容展开、天气页侧栏淡出与 `Esc` 返回、少量 Hover/过渡/毛玻璃效果。

预览不支持：登录、同步、上传、真实 PDF 处理、真实 AI 请求、真实文件读写或个人数据导入。

桌面验收基准为 1280×800；同时检查约 980px 宽窗口下的侧栏收起和内容不溢出。预览通过本地静态服务打开。

## 8. 后续 Flutter 组件边界

确认预览后，Flutter 改造应优先形成以下独立单元：

- `WorkbenchShell`：一级导航、侧栏状态、当前工作区和返回状态。
- `PageScaffold`：标题、短说明、二级导航、主操作和内容边距。
- `WorkspaceTabs`：工作区内的短横向标签与状态保持。
- `GlassSurface`：限制模糊强度、透明度、降级模式和使用场景。
- `WeatherStandbyView`：手动进入、侧栏显隐、返回现场恢复。
- `FeedbackBanner`、`EmptyState`、`LoadingSkeleton`：统一反馈模式。

组件不得直接依赖具体业务模型；页面负责把业务数据转换成组件需要的展示属性。

## 9. 数据流与状态恢复

导航状态由应用壳层持有：当前一级工作区、当前二级标签、每页滚动位置、筛选条件和选中对象分别保存。打开天气页前记录导航快照；退出天气页时恢复快照，不重新初始化目标页面。

Web 原型只使用内存中的演示状态。Flutter 阶段继续使用现有 Controller/Repository 数据源，视觉组件不直接访问数据库或 API。

## 10. 错误、加载与空状态

- 可恢复错误显示在发生区域附近，使用一行信息和一个“重试”操作。
- 全局同步异常使用壳层状态入口，不在每个页面重复弹出 Snackbar。
- 破坏性操作必须二次确认，并明确影响对象。
- 首次加载使用结构匹配的骨架，不使用全屏转圈遮挡工作台。
- 空状态只包含一句说明和一个主要操作。

## 11. 业务逻辑审计结论

现有自动化基础较好：Flutter 180 个测试全部通过；后端 13 个测试全部通过；Dart 分析只有 1 条无害 warning 和 5 条风格提示。但以下问题不应因测试通过而忽略：

### P0：同步冲突策略与 PRD 不一致

后端事件更新对较低版本没有拒绝或冲突记录，仍直接覆盖并递增版本（`EventEntryService.java:69–98`）。客户端 Outbox 对同一实体的连续更新逐条插入，不做合并（`sync_outbox_repository.dart:26–46`）。跨设备编辑可能成为隐式“后推送覆盖先修改”，而不是 PRD 所述的冲突提示与自动策略。

### P0：离线启动可能错误清除登录会话

应用启动调用 `/me` 时，除 401 刷新分支外的 API 异常会清除本地会话；未知异常同样清除（`auth_controller.dart:78–99`）。服务器暂时不可用或网络中断不应等同于凭证失效，这与离线优先目标冲突。

### P1：手动日程缺少删除闭环

日历编辑器只有新增和更新分支（`calendar_page.dart:724–760`），控制器对应 `addManualEvent` 与 `updateEditableEvent`，没有手动日程删除及云端删除入队路径。当前实现未满足 PRD 中手动事项 CRUD 的“删除”。

### P1：PDF 操作的 Token 自动刷新不完整

`pdfOperationApi` 创建的 `ApiClient` 只提供 Access Token 读取器，没有 `onUnauthorized` 刷新回调（`research_life_controller.dart:1263–1265`）。Access Token 到期后，PDF 操作可能直接返回 401，而文件同步与 AI 助手能够自动刷新。

### P1：重命名文件夹未级联更新子路径

移动文件夹会调用 `updateChildrenRelativePaths`（`FileEntryService.java:205–212`），但重命名只更新当前节点路径并保存（`FileEntryService.java:268–295`）。重命名含子节点的文件夹后，后代 `relativePath` 可能保留旧路径。

### P2：同步队列需要合并与可观察性

Outbox 当前总是插入新行，并一次只取前 100 条（`sync_outbox_repository.dart:26–53`）。高频编辑可能堆积同实体更新、增加重试噪声。后续应按实体合并未发送更新，保留删除优先级，并提供明确的失败详情与重试入口。

## 12. 验收与测试

Web 预览验收：

- 导航映射与本规格一致。
- 页面说明文字满足克制规则。
- 毛玻璃只出现在允许区域，文字对比度清晰。
- 1280×800 下首屏无裁切；约 980px 宽下无水平溢出。
- 天气页只能手动进入，`Esc` 返回原页面状态。
- 所有导航、标签、收起和选中交互均有明确反馈。

Flutter 实施阶段的最低验证：

- 保留并扩展现有前后端测试。
- 为手动日程删除、离线启动、Token 刷新、文件夹重命名级联和同步冲突增加回归测试。
- Windows 桌面端检查展开/收起侧栏、天气待机返回、宽窄窗口和减少动态/透明模式。
- 使用 Flutter 实机截图与确认后的 Web 设计逐项比对，Web CSS 数值不作为 Flutter 实现的直接来源。
