# 研LIFE Flutter 本地单机版改造设计

日期：2026-08-09  
状态：用户已审核确认，进入实施计划阶段

## 1. 目标

将研LIFE 从包含登录、跨设备同步和云文件能力的 Flutter Windows 应用，调整为以单台设备长期使用为目标的本地个人工作台；同时把已经确认的 Web 视觉方案落地到 Flutter。

本地数据库、本地工作区和本地资料清单成为唯一可信数据源。天气与 AI 可以按需联网，但不依赖工作台账号。应用必须在断网状态下正常启动并完整访问本地功能。

## 2. 已确认的产品边界

- 不需要登录、注册、退出登录、Access Token 或 Refresh Token。
- 不需要跨设备同步、云文件、同步冲突处理或设备身份。
- 不存在必须迁回本机的云端独有数据。
- 允许天气和 AI 独立联网；网络失败不得阻塞工作台启动。
- 保留本地 PIN、隐私屏、托盘、提醒和桌宠等单机能力。
- Web 页面继续只作为视觉验收参考，不成为正式应用运行时依赖。
- Flutter 改造期间不得丢失现有本地数据库、资料清单或工作区文件。

## 3. 采用的改造策略

采用分阶段本地化，不一次性删除全部云端代码。

第一阶段先改变运行行为：应用直接进入本地工作台，停止创建和调用登录、Token、Outbox、云文件和同步服务；所有业务写入只进入本地仓储。旧同步表和同步字段暂时保留，避免在 UI 重构期间同时执行破坏性数据库迁移。

第二阶段在本地版通过数据恢复与功能回归后，删除确认无引用的认证、同步和云文件代码，并通过独立数据库迁移移除废弃结构。第二阶段不得与第一阶段共享同一个不可回滚的数据迁移。

## 4. 应用启动与依赖结构

当前 `ResearchLifeApp` 在启动时创建 `AuthController`、带 Token 的 `ApiClient`、`SyncOutboxRepository`、`CloudFileService` 和 `FileSyncEngine`，再通过 `AuthGate` 进入 `AppShell`。本地版调整为：

1. 初始化本地工作区、Drift 数据库和本地仓储。
2. 初始化备份、天气、提醒、托盘、桌宠和可选 AI 适配器。
3. 加载本地偏好与必要的启动数据。
4. 直接构建 `PinLockGate(child: AppShell())`。

本地运行主链路不创建认证、Token、同步队列、设备 ID 或云文件服务。旧服务在第一阶段可继续存在于源码中，但不得位于启动依赖图内。

## 5. 数据与服务边界

### 5.1 唯一数据源

- 结构化数据：Drift 数据库。
- 资料文件：用户本地工作区目录。
- 文献和文件清单：本地清单存储与对应仓储。
- 用户偏好：现有偏好仓储；敏感 AI 凭据写入 Windows 凭据管理器，并由独立凭据接口读取，不得写入普通数据库、日志或备份。若系统凭据存储不可用，AI 保持未配置状态，不降级为明文持久化。

新增、修改和删除操作直接提交本地事务，不再生成 Outbox 项，不等待网络确认，也不维护“待同步”“已同步”等用户可见状态。

### 5.2 可选联网能力

天气和 AI 分别通过独立接口接入：

- 天气服务无需工作台账号；失败时继续展示最近一次成功数据，并显示克制的刷新提示。
- AI 只属于科研工作区。服务地址和模型在本机配置；凭据通过 Windows 凭据管理器保存，不进入普通配置导出。
- 任一网络服务不可用时，只降级对应页面，不影响本地资料、日程、笔记和设置。

### 5.3 仍需补齐的本地业务闭环

- 手动日程删除：补齐确认、数据库删除、关联待办状态清理和 UI 刷新。
- 文件夹重命名级联：在单个事务内更新文件夹及全部后代相对路径；失败时整体回滚。

此前发现的同步冲突、离线误清登录状态和 PDF Token 刷新问题，在本地运行主链路删除后不再成立，不单独修补旧云端实现。

## 6. 本地备份与恢复

本地备份替代原同步入口，覆盖数据库、资料清单、工作区文件、非敏感偏好、备份格式版本和完整性校验信息。

- 第一次启动本地版前自动创建迁移安全备份。
- 自动备份默认保留最近 10 份。
- 支持手动选择任意本地目录；OneDrive、移动硬盘或 NAS 映射目录仅被视为普通文件夹，应用不负责其账号和同步。
- 备份先写入临时目标，完成清单和校验后再原子替换为正式备份。
- 创建备份前等待待持久化任务完成，通过互斥锁暂停新的写操作，执行 SQLite WAL checkpoint 后再复制数据库与文件清单；完成或失败后释放写入锁。
- 恢复前校验格式版本、文件完整性和必要文件；不兼容或损坏时不得覆盖当前数据。
- 执行恢复前自动备份当前状态。
- 恢复时先关闭数据库和持有工作区文件的服务，校验通过后原子替换目标文件；完成后重新打开数据库并重新加载控制器状态，不混用恢复前缓存。
- AI 凭据、临时缓存和可重新获取的天气缓存默认不进入可移植备份。

## 7. 信息架构与导航

一级导航固定为：

1. 天气
2. 今天
3. 科研
4. 资料
5. 生活
6. 设置（底部固定）

现有功能不因导航精简而删除，而是归入工作区二级标签：

| 工作区 | 二级入口 |
| --- | --- |
| 今天 | 今天、日历、待办 |
| 科研 | 概览、文献、笔记、周分析、人物、统计 |
| 资料 | 文件、文档查看、PDF 工具 |
| 生活 | 校园、桌宠、个性化 |

AI 只作为科研工作区的辅助操作。历史记录成为相关科研页面的回溯入口，不作为一级导航。

## 8. Flutter 组件边界

- `WorkbenchShell`：一级导航、侧栏状态、当前工作区、天气返回快照和宽窄窗口布局。
- `PageScaffold`：页面标题、最多一行短说明、二级标签、主操作和统一内容边距。
- `WorkspaceTabs`：工作区内标签选择与状态保持。
- `GlassSurface`：允许的模糊、透明度、不透明降级和使用位置。
- `WeatherStandbyView`：手动进入、时间天气显示、动画控制和返回现场恢复。
- `LocalBackupService`：备份清单、原子写入、校验、轮换和恢复。
- `FeedbackBanner`、`EmptyState`、`LoadingSkeleton`：统一局部反馈。

视觉组件只接收展示模型和回调，不直接访问数据库、文件系统或网络。页面或控制器负责把仓储数据映射成展示属性。

## 9. 状态保持

`WorkbenchShell` 持有当前一级工作区，并为每个工作区分别保存当前二级标签。各页面使用稳定 Key、懒加载和保活策略保存筛选条件、选中对象和滚动位置。

打开天气页前记录导航快照，包括一级工作区、二级标签和必要的页面恢复标识。天气页只能手动打开。按 `Escape` 或返回按钮时恢复快照，不重新初始化目标页面。

## 10. 天气页设计

天气页以确认后的高清云景构图为稳定底图。静态状态本身必须达到最终视觉质量，动画仅作为增强。

可选动画限制为低速、低干扰和低开销的图层：

- 两到三层薄云缓慢视差。
- 柔和光线或亮度漂移。
- 与天气类型匹配的少量粒子；晴朗天气不强行添加粒子。

背景动画、时间刷新和天气数据更新使用独立的重绘边界。时钟每秒更新不得重绘整张天气背景。动画关闭、系统启用减少动态、窗口不可见或页面离开时必须停止 ticker。

用户关闭动画、系统启用减少动态、天气页离开前台或 Flutter `TickerMode` 被关闭时，天气页停留在同一张静态构图，不替换成低质量占位背景。天气页同时提供不透明材质降级，减少 `BackdropFilter` 数量。

## 11. 视觉系统

- 以确认的 Web 预览为视觉参考，保留学术绿、冷浅色内容区和克制说明文字。
- 侧栏展开约 216–224px，收起约 68–80px；收起和紧凑模式保留 Tooltip。
- 一级工作区采用统一页面标题、二级标签和一个主要操作。
- 毛玻璃只用于天气信息层、品牌或搜索、浮动工具栏、对话框和状态提示。
- 普通列表、文件表格、PDF 阅读底板和滚动正文不得使用毛玻璃。
- 页面切换和控件反馈约 140–220ms；尊重系统减少动态设置。
- 主题只改变颜色，不改变组件结构、排版、间距和信息层级。

## 12. 错误与恢复策略

- 本地仓储错误显示在对应区域附近，提供一句说明和一个可执行操作。
- 备份或恢复失败必须保留当前数据，并展示可定位的失败阶段。
- 天气和 AI 网络错误不弹出连续全局提示，也不阻止本地启动。
- 文件夹级联重命名使用 Drift 事务；恢复操作使用已校验临时目录与同卷原子替换，任一步骤失败都保留恢复前数据。
- 破坏性操作必须明确对象并二次确认。
- 启动加载使用结构匹配的骨架或局部状态，不使用长期全屏转圈。

## 13. 实施阶段

### 阶段 A：本地数据保护

1. 为备份格式、原子写入、轮换、校验和恢复增加测试。
2. 实现迁移前安全备份。
3. 记录现有本地数据基线并验证恢复一致性。

### 阶段 B：切换本地运行主链路

1. 直接进入 `PinLockGate → AppShell`。
2. 从启动依赖图移除认证、Token、同步、云文件和设备 ID。
3. 让资料、文献、笔记、日程和 PDF 使用纯本地仓储。
4. 将同步设置替换为备份与恢复。

### 阶段 C：补齐本地业务逻辑

1. 实现手动日程删除闭环。
2. 实现文件夹重命名后代路径事务级联。

### 阶段 D：Flutter 界面改造

1. 改造 `WorkbenchShell`、`PageScaffold`、`WorkspaceTabs` 和公共视觉组件。
2. 按今天、科研、资料、生活、设置的顺序迁移现有页面。
3. 实现天气静态底图、轻动态和减少动态/透明降级。
4. 使用 Windows 实机截图逐项对照确认后的 Web 预览。

### 阶段 E：删除废弃云端实现

1. 根据静态引用和测试结果删除认证、同步、云文件及相关页面和测试。
2. 单独设计并执行数据库清理迁移。
3. 确认后端不再属于桌面本地版交付范围；本阶段不删除仓库外或仍被其他客户端使用的服务。

## 14. 测试与验收

自动化最低覆盖：

- 无登录启动并进入工作台。
- 完全断网时本地数据、文件、日程、笔记和设置可用。
- 迁移前备份、自动轮换、损坏备份拒绝、恢复前备份和恢复一致性。
- 手动日程删除及关联状态清理。
- 文件夹重命名后所有后代路径正确；中途失败整体回滚。
- 一级导航、二级标签状态保持和天气返回快照。
- 天气动画开关、减少动态、页面离开停止 ticker。
- 减少透明度下不创建不必要的模糊层。
- 现有有效 Flutter 测试继续通过；删除云端测试必须与对应实现删除发生在同一阶段。

Windows 实机验收：

- 1280×800 和约 980px 宽窗口无水平溢出或关键内容裁切。
- 展开/收起侧栏、紧凑 Tooltip、键盘焦点和 Escape 返回正常。
- 天气静态状态足够完整，动画开启后不影响文字可读性或交互响应。
- 今天、科研、资料、生活的视觉层级与 Web 预览一致。
- 应用启动、退出、托盘恢复、备份和恢复过程中不丢失数据。

## 15. 非目标

- 不实现账号体系或跨设备实时同步。
- 不提供应用内 OneDrive、网盘或 NAS 登录。
- 不在本阶段重写 AI、天气或 PDF 算法。
- 不把 Web 代码嵌入 Flutter。
- 不在第一阶段删除数据库同步字段或旧同步表。
- 不因视觉重构修改与本地化无关的科研计算规则。
